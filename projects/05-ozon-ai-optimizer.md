> 💼 公司商业项目，源码不公开。本文档描述方案、我的职责、技术难点与成果。

## 📌 项目背景

帮卖家自动优化 Ozon 平台商品的"内容分"（标题 / 属性 / 富内容 / 图片），从而提升搜索排名。

## 🙋 我的职责

独立完成 AI 优化逻辑、平台 API 对接、商业化打包授权。

## 🏗️ 流程

```
读取商品 ──▶ 大模型分析缺失项 ──▶ 生成属性/富内容文案 ──▶ 写回平台
   │              │ Prompt 工程           │                  │
   │              └─ 输出校验/规则兜底      │            Ozon 商品/图片/
   └──────────────────────────────────────┘            富内容接口
```

## 🔑 核心实现

- **大模型集成**：用 Claude API + Prompt 工程，自动补全商品属性、生成符合平台规则的富内容文案
- **平台对接**：调用 Ozon 商品信息 / 图片导入 / 富内容接口写回（注意图片导入是替换模式而非追加）
- **AI 输出治理**（亮点）：模型偶尔返回非法值（如颜色属性返回 "A"），通过追加 Prompt 规则 + 输出校验兜住，保证写回数据合法
- **商业化授权**：激活码 + 心跳验证模型（订阅挂在激活码上而非账号上），PyInstaller + PyArmor 打包加固

## 🐛 难点（面试可讲）

- Ozon 富内容 JSON 审核拒绝、正文过短不通过 → 调整生成策略满足审核规则
- 评分更新有 1-3 分钟延迟，多次被误判为"写回失败" → 加重试 + 延迟确认逻辑
- 平台某些接口对 PNG 透明图无法直接存 JPEG、字段类型不一致（字符串/列表）→ 做兼容处理
- PyArmor 试用版对大文件有限制 → 按预案降级，不阻塞交付

## 📊 成果

| 指标 | 结果 |
|---|---|
| 优化效果 | 单商品内容分做到满分 10/10 |
| 商业化 | 激活码 + 心跳授权，多版本交付 |
| AI 工程 | 处理了 AI 输出不可控的真实问题（非调个 API 就完事） |

## 💡 为什么这个项目对"AI 应用开发岗"重要

这是我**最早把大模型真正用进生产业务**的项目。重点不是"会调 API"，而是处理了 AI 应用落地的真实工程问题：**输出不可控如何兜底、如何满足下游平台的硬规则、如何把 AI 嵌进端到端业务流**。
