> 💼 公司商业项目，源码不公开。本文档描述架构、我的职责、技术难点与成果。

## 📌 项目背景

让卖家在 1688 商品页**直接下采购单（代发直发买家）**，打通某采购网关的 5 步下单链路（授权 → 商品信息 → 下单预览 → 创建订单 → 订单详情）。

## 🙋 我的职责

独立完成**插件 + 后端代理**的全栈开发。

## 🏗️ 架构（安全是设计核心）

```
卖家在 1688 商品页
      │
      ▼
┌──────────────────────┐   员工账号登录(JWT)   ┌──────────────────────────┐
│  Chrome MV3 插件       │ ───────────────────▶ │  公司后端代理 (FastAPI)      │
│  (纯 JS，不含任何密钥)  │                      │  · 写死网关密钥(仅服务端)    │
│  读商品ID/SKU/下单UI    │ ◀─────────────────── │  · 校验员工 + 记录谁下的单    │
└──────────────────────┘     订单结果           │  · 代理网关 5 步 + 落库      │
                                              └──────────────────────────┘
                                                          │
                                                          ▼
                                                   采购网关 → 1688
```

**为什么这样设计**：网关密钥（oak）一旦下放到插件就等于公开泄露。所以密钥**只写死在后端服务端**，插件用员工账号登录、后端注入密钥并记录操作人，既安全又可审计。

## 🔑 核心实现

**后端（FastAPI）**
- 员工鉴权：bcrypt 密码 + JWT
- 代理网关 5 步下单链路，订单落库（SQLite）
- **幂等**：后端生成 `requestNo`，避免重复下单
- **健壮性**：失败重试 + 网络异常时查订单 detail 兜底（防"下单成功但响应丢失"）
- **错误分类**：网关真实报错藏在 `subMsg` 字段（`msg` 常是无用的"执行失败"），提取出来返回给前端

**插件（Chrome MV3，纯 JS 零构建）**
- 读取当前商品页 offerId、加载 SKU 规格
- 授权引导、收货地址手填、下单预览、提交、订单查询
- 选择零构建纯 JS（而非 Vite+TS）—— 规避 Windows 下 MV3 构建链的不稳定，优先稳定与最简

## 🐛 难点（面试可讲，都很真实）

- `passlib` 与 `bcrypt 4.x` 不兼容（报 72 字节错误）→ 改为直接调用 bcrypt
- 网关线上返回字段名与文档不符（如规格属性字段名、库存字段名不同，甚至接口字段有拼写 typo）→ 以线上实测为准重新对齐解析
- 订单 ID 是**字符串**，直接当数字会被 JS 丢精度 → 全程按字符串处理
- 网关下单预览返回的是嵌套数组结构（与文档的扁平结构不同）→ 按实际结构解析
